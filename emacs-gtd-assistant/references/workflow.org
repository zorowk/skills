#+title: Org GTD 技能工作流

* 配置与入口
通过 emacsclient 按需加载 =scripts/emacs-gtd-assistant.el=，调用 =emacs-gtd-execute=。
技能不安装 Org、Agenda 或 Agent Shell 快捷键，不筛选、恢复或绑定 AI 会话，也不改变日志存储路径。

- =emacs-gtd-directory=：GTD 文件目录，默认 =~/Dropbox/brain/=。
- =emacs-gtd-file=：主文件名，默认 =gtd.org=。
- =emacs-gtd-extra-files=：额外允许管理的 Org 文件，默认空列表。

只操作主文件及明确配置的额外文件；Agenda 文件不会自动加入管理范围。
需要管理 =notes.org= 时，将其绝对路径加入 =emacs-gtd-extra-files=。
跨文件移动工作项后，确保目标文件仍在管理范围内。重复 ID 会报歧义。

* 从讨论到执行
先选择项目或任务，通过 =get= 读取条目与最近项目的资料。
=create-project= 或 =configure-project= 设置项目目录与文档链接。
确认需求与架构文档后，明确让 AI 通过 =add-children= 将实施步骤写成项目下的 Org 子任务。
任务正文写目标与验收条件，CONTEXT 写当前接续点，LOGBOOK 写有日期的结果。
通过项目级资料和任务上下文接手，不需要每次重读全部聊天。

一般任务使用 =add=、=add-many=、=list=、=resolve=、=set-state= 等操作。
修改需要明确授权；讨论下一步不等于授权创建任务。
收尾时按用户要求通过 =add-note= 和 =set-context= 记录结果与接续点，
不因 AI 回合结束自动标记 DONE，不隐式提交或推送。

* 数据约定
- ID：项目与每个工作项各自唯一，不能继承父项目的 ID。
- PROJECT_DIR：最近一个包含此属性的标题是当前工作项的项目。
- RESOURCES：仓库与需求、架构等文档的 Org 链接，包括按要求关联的 Denote 笔记。
- CONTEXT：短接续说明。
- LOGBOOK：收尾结果、实际验证及阻塞。

旧集成写入的 AI_SESSIONS 抽屉和已有会话文件保留，技能不再维护会话记录。
