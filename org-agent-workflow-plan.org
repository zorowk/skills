#+title: Org 驱动的 AI 项目工作流改造
#+startup: overview

* 目标与约定
由用户选择目标、任务和工作节奏；从 Org/Agenda 进入对应 AI 会话。
先讨论形成需求、架构等项目文档，再按用户指令将实施步骤写成 Org 子任务。
项目文档保存在项目仓库，链接挂到 Org 项目；Org 本身承担实施计划与进度。
不使用 Hyperbole，不自动创建后续任务，不因 AI 回合结束而标记 DONE。
聊天记录和截图集中保存到 ~/Dropbox/.agent-shell/；后端原生会话不承诺跨机恢复。

本文件是这次改造的实施任务树；完成过程中直接更新，不另建实施文档。

* DONE 1. 建立项目与任务的数据契约
- 项目：独立 ID、PROJECT_DIR、仓库与主要文档 RESOURCES 链接。
- 任务：独立 ID、目标/验收/接续信息、归属项目。
- 会话：任务 ID、agent 配置、session ID、聊天记录路径，可一任务多会话。
- get/list 查询不修改 Org；写入必须经统一 facade，并遵守已有显式授权。
  保留原有 resolve 在唯一匹配时补建 ID 的兼容行为。
- 支持 Agenda 中现有两个文件，不只支持 gtd.org。
- 验收：可读取父项目资料；任务移动/改名后仍按 ID 识别；不继承父 ID。

* DONE 2. 扩展 Org facade 与 skill
- 增加读单个条目及项目上下文、项目配置、按父 ID 添加子任务的操作。
- 保留原有查询、状态、链接与日志功能，避免破坏 Denote 等调用方。
- 明确用户发起的项目拆分不受“聊天候选最多三项”限制。
- 明确讨论到文档到任务的工作方式，现有授权足够时直接执行。
- 验收：隔离临时 Org 文件测试层级、授权、写入和原有兼容行为。

* DONE 3. 接入 agent-shell
- 入口沿用 C-z a：从 Org 或 Agenda 识别项目，先选 AI，再选该项目会话。
- 按明确 PROJECT_DIR 识别项目；普通待办不建 ID，保留原生行为。
- 保存本次工作项与所选会话的关联；同项目子任务共享会话候选。
- 无可恢复会话时可新建，并预填目标、文档入口和接续信息，等待用户发送。
- 收尾命令预填总结请求，由 AI 通过 facade 更新任务日志/接续信息。
- 存储按项目 ID 分目录；非 Org 会话也集中保存，按路径摘要隔离。
- 不自动移动旧记录，不重定位已运行会话的 transcript。
- 验收：mock agent API 验证复用、恢复/新建分支、异步关联与存储隔离。

* DONE 4. 配置 Emacs 用户入口
- init-llm.el 加载技能仓库中的集成模块，配置 Dropbox 存储位置。
- Org 和 Agenda 使用相同的开始/继续及收尾快捷键。
- 沿用原来的 Agenda 视图，不增加额外工作视图。
- 保留原有 agent、代码上下文和个人任务配置。
- 验收：批处理配置检查，并在运行中的 Emacs 验证命令和只读上下文。

* DONE 5. 验证与交付
- 执行相关 ERT、skill frontmatter 校验，检查两个仓库差异。
- 如存在失败，区分新问题与已有问题；记录已执行的证据。
- 提供开始/继续、收尾的实际操作方式。
- 本次不创建 Mahjong 项目，不更改现有任务状态，不提交 Git。
